You are given a C function. Replace only the code between the markers
#pragma scop
and
#pragma endscop
with equivalent 8086 assembly, written as a GCC extended inline asm() block
compatible with ia16-elf-gcc.

Requirements:
- Assembler syntax is GNU as / AT&T syntax (ia16-elf-gcc's assembler is a
  GNU binutils port). Do NOT use NASM or Intel syntax. Never write the word
  "ptr" anywhere -- that is an Intel-syntax keyword and does not exist in
  AT&T syntax at all.
- Target is real Intel 8086, small memory model: near pointers only, code
  and data each fit in 64KB.
- Registers are natively 16-bit: ax, bx, cx, dx, si, di, bp, sp. There is no
  eax/rax to fall back on -- do not use 32-bit or 64-bit register names.

Memory addressing on real 8086 is extremely restricted -- read this
carefully, most incorrect assembly comes from violating these two rules:

1. The ONLY legal memory addressing forms are:
     (%bx), (%si), (%di), (%bp),
     (%bx,%si), (%bx,%di), (%bp,%si), (%bp,%di),
   each optionally with a constant displacement in front, e.g.:
     -2(%di)      correct: displacement -2, base register di
     4(%bx,%si)   correct: displacement 4, base bx, index si
   There is NO scale factor. A form like -2*%di or 2*%si(%bx) is not real
   8086 addressing and will not assemble. If you catch yourself writing a
   "*" next to a register to compute an address, stop -- that syntax is
   for 32/64-bit x86 and does not exist here. Multiply the index into a
   register first (e.g. with shl or imul) and use plain register-only
   addressing like (%bx,%si) instead.

2. No instruction may have two memory operands. Something like
   "movw (%bx), (%di)" is illegal on any x86, not just an ia16-elf-gcc
   restriction. Always move one operand into a register first, then
   operate between that register and the second memory location:
     movw (%bx), %ax
     movw %ax, (%di)
   NOT:
     movw (%bx), (%di)

- Preserve the exact surrounding function signature and behavior.
- Use explicit input/output/clobber lists in the asm() block. Do not
  clobber a register that's still needed as an address/loop variable
  later in the same block.
- Return ONLY the replacement code that goes between the two pragma
  markers (not the whole file, not the function signature, not the
  pragma lines themselves) -- no explanation, no markdown code fences.
