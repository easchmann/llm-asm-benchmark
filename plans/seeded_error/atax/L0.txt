Registers (System V)
- All six arguments arrive in registers, none on the stack: m in rdi, n in rsi, A in rdx, x in rcx, y in r8, tmp in r9.
- rdx is used as the pointer to the current row of A and advances by 8*n bytes per row, so no separate row index is needed.
- rdi counts the remaining rows down from m to 0; r9 advances by 8 bytes per row and points at tmp[i].
- r10 is the column index j. r11 holds n rounded down to a multiple of 4 (n & -4), the end of the vector part.
- Only caller-saved registers are used (rdi, rsi, rdx, rcx, r8, r9, r10, r11, ymm0-ymm5), so nothing is pushed or saved and the stack is not touched.

Loops
1. y keeps its initial contents: the products are added to the values already in y, so it is not cleared.
2. For each row i (m iterations, row pointer rdx = A + 8*n*i):
   a. Dot product s = sum over j of A[i][j] * x[j]. Address of A[i][j] is rdx + 8*j, of x[j] is x + 8*j.
      Vector part: j from 0 while j < r11 in steps of 4, accumulating four partial sums in one 256-bit register.
      Then add the four lanes into one scalar (upper 128 bits onto the lower 128 bits, then the two remaining lanes).
      Scalar part: j < n, adding one product at a time to the scalar sum.
   b. Store s to tmp[i] at address r9.
   c. Update y[j] += A[i][j] * s for all j: broadcast s to four lanes (from tmp[i] in memory), vector part j < r11 in steps of 4 (load A[i][j..j+3], multiply by s, add y[j..j+3], store y[j..j+3]), then a scalar part for j < n.
   d. Advance rdx by 8*n, r9 by 8, decrement rdi, loop while rdi > 0.
3. Clear the upper halves of the ymm registers (vzeroupper) and return.

Edge cases
- m = 1: the row loop runs once. n = 1, 2 or 3: r11 = 0, so every vector loop is skipped and only the scalar loops run.
- n not a multiple of 4: the scalar loops handle the last n mod 4 columns; no load or store touches index n or beyond in any array.
- Every loop tests its condition before the first iteration, so no loop body runs with a count of zero.
- Arrays of doubles are only guaranteed 8-byte alignment: all vector loads and stores are unaligned.

Vector instructions
- AVX with 256-bit registers (4 doubles per vector). No FMA, since FMA is not in the allowed set: multiply and add are separate instructions.
- Scalar operations use the VEX-encoded (AVX) forms as well, to avoid mixing legacy SSE and AVX encodings.
- Because the dot product is summed in four lanes, the order of additions differs from a sequential sum; results agree up to rounding.
