x86-64 reference (GNU as, AT&T syntax, System V, SSE2/AVX/AVX2)

AT&T syntax pitfalls
- Operand order is source first, destination last: "addq %rsi, %rax" means rax = rax + rsi. For three-operand AVX forms the destination is last: "vaddpd %ymm2, %ymm1, %ymm0" means ymm0 = ymm1 + ymm2; "vsubpd %ymm2, %ymm1, %ymm0" means ymm0 = ymm1 - ymm2.
- Registers take %, immediates take $. A constant without $ is a memory address.
- Memory operands are disp(base, index, scale) with scale 1, 2, 4 or 8: "vmovupd (%rsi,%rcx,8), %ymm1" loads x[i..i+3] when rsi = x and rcx = i.
- Size suffixes: q = 64-bit, l = 32-bit. Writing a 32-bit register zeroes the upper 32 bits; write 64-bit registers for pointers and sizes.
- 64-bit constants need "movabsq $imm64, %reg"; most other instructions only take sign-extended 32-bit immediates.
- Floating-point constants come from memory, e.g. a ".section .rodata" entry ".align 8 / C: .double 0.2", loaded with "vbroadcastsd C(%rip), %ymm15". Return to ".text" afterwards.
- Export with ".globl name" and define "name:" in .text.

System V ABI
- Integer and pointer arguments: rdi, rsi, rdx, rcx, r8, r9; further ones on the stack at 8(%rsp), 16(%rsp), ... on entry (0(%rsp) is the return address). Each push moves them 8 bytes further away.
- double arguments: xmm0-xmm7, counted separately from the integer ones. A double result returns in xmm0, an integer result in rax.
- Caller-saved (free to use): rax, rcx, rdx, rsi, rdi, r8-r11, all xmm/ymm registers.
- Callee-saved: rbx, rbp, r12-r15 (and rsp). Push the ones you use at entry and pop them in reverse order before ret.
- Long and pointer comparisons: signed conditions are l, le, g, ge (jl, cmovg); unsigned are b, be, a, ae.

SSE2/AVX/AVX2 for double arrays
- ymm holds 4 doubles, xmm holds 2. Use the VEX (v-prefixed) forms throughout; do not mix them with legacy SSE forms.
- Unaligned loads and stores: vmovupd. Broadcast a scalar: vbroadcastsd mem, %ymm (AVX), or vbroadcastsd %xmm, %ymm (AVX2).
- Arithmetic: vaddpd, vsubpd, vmulpd, vdivpd, vsqrtpd; scalar forms vaddsd, vmulsd, vsqrtsd, vmovsd. FMA (vfmadd...) is not part of AVX2 and is not allowed.
- Zero a register: vxorpd %ymm0, %ymm0, %ymm0.
- Execute vzeroupper before ret whenever ymm registers were used; it keeps xmm0, so a double result survives.
- POPCNT, LZCNT and BMI instructions are not part of SSE2/AVX/AVX2.

Horizontal reduction of four doubles in ymm0 into xmm0
    vextractf128 $1, %ymm0, %xmm1
    vaddpd %xmm1, %xmm0, %xmm0
    vunpckhpd %xmm0, %xmm0, %xmm1
    vaddsd %xmm1, %xmm0, %xmm0
The result differs from a sequential sum only by rounding.

Tails (sizes that are not a multiple of the vector width)
- Simplest: vector part for i < (n & -4) in steps of 4, then a scalar part for the remaining i < n. Test each bound before the first iteration, so sizes below 4 skip the vector part.
- Never load or store past the last element, even if the result would be discarded; tests check guard bytes around every array.
- Masked alternative: vmaskmovpd with a mask of all-ones lanes for valid elements; masked-off lanes are neither read nor written.

Common mistakes
- Clobbering an argument register before its last use.
- Forgetting that the (%rsp) offsets of stack arguments change after each push.
- Using 32-bit registers for 64-bit sizes or indices.
- Stack misalignment does not matter when no function is called, but pushes and pops must balance before ret.
