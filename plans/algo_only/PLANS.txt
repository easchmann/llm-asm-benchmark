=== axpy
Algorithm
1. For i from 0 while i < n: y[i] = y[i] + a * x[i].

Edge cases
- n = 1: a single element.
- Nothing at index n or beyond is read or written.
=== scal
Algorithm
1. For i from 0 while i < n: x[i] = x[i] * a.

Edge cases
- n = 1: a single element.
- No access at index n or beyond.
=== nrm2
Algorithm
1. s = 0.
2. For i from 0 while i < n: s = s + x[i] * x[i].
3. Return the square root of s.

Edge cases
- n = 1 returns |x[0]|, since sqrt(x*x) is the absolute value.
- No read beyond index n-1.
- The sum of squares is computed directly without rescaling.
=== dot
Algorithm
1. s = 0.
2. For i from 0 while i < n: s = s + x[i] * y[i].
3. Return s.

Edge cases
- n = 1: the result is x[0] * y[0].
- Nothing beyond index n-1 is read.
=== atax
Algorithm
1. Clear y: y[j] = 0 for every j from 0 to n-1. y must be cleared because its initial contents are undefined.
2. For each row i from 0 while i < m:
   a. Dot product s = sum over j of A[i][j] * x[j], with A[i][j] at index i*n + j of A.
   b. Store s to tmp[i].
   c. Update y[j] = y[j] + A[i][j] * s for all j from 0 to n-1.
3. Return.

Edge cases
- m = 1: the row step runs once. n = 1: each row has a single element.
- No access touches index n or beyond in any row or vector.
- No loop body runs with a count of zero.
- Because the dot product can be summed in a different order from a sequential sum, results agree up to rounding.
=== bicg
Algorithm
A has n rows and m columns (A[i][j] at index i*m + j).
1. Clear s: s[j] = 0 for j from 0 to m-1, because s is undefined on entry.
2. For each row i from 0 while i < n:
   - sum = 0.
   - For j from 0 while j < m: sum = sum + A[i][j] * p[j]; s[j] = s[j] + A[i][j] * r[i].
   - q[i] = sum.
3. Return.

Edge cases
- n = 1: one row. m = 1: one column.
- s is cleared before accumulating; q is written once per row.
=== mvt
Algorithm
One pass over A, row by row, doing both products:
1. For each row i from 0 while i < n:
   - sum = 0.
   - For j from 0 while j < n: sum = sum + A[i][j] * y_1[j]; x2[j] = x2[j] + A[i][j] * y_2[i].
   - x1[i] = x1[i] + sum.
2. Return.

Edge cases
- n = 1: a single element.
- x1 and x2 keep their initial values and are only added to.
- x2 receives the contributions of the rows in row order.
=== gemver
Algorithm
1. Update A: for each row i, for all j: A[i][j] = (A[i][j] + u1[i]*v1[j]) + u2[i]*v2[j].
2. x += beta * A^T y, using the updated A row by row: for each row r: t = beta * y[r]; x[c] = x[c] + t * A[r][c] for all c.
3. x += z: for all c, x[c] = x[c] + z[c].
4. w += alpha * A x: for each row i: d = sum over j of A[i][j] * x[j] with the updated x; w[i] = w[i] + alpha * d.
5. Return.

Edge cases
- n = 1: every step works on single elements.
- The steps must run in this order: step 2 uses the fully updated A, step 4 uses x after steps 2 and 3.
=== gesummv
Algorithm
1. For each row i from 0 while i < n:
   - sA = sum over j of A[i][j] * x[j]; sB = sum over j of B[i][j] * x[j].
   - tmp[i] = sA; y[i] = alpha * sA + beta * sB.
2. Return.

Edge cases
- n = 1: one element per row.
- No read beyond column n-1.
- y is written for every i, so its undefined initial contents do not matter.
=== trmv
Algorithm
1. For each row i from 0 while i < n:
   - sum = 0; for j from 0 while j <= i: sum = sum + L[i][j] * x[j].
   - y[i] = sum.
2. Return.

Edge cases
- Only columns 0 to i of row i are read, so the arbitrary values above the diagonal are never used.
- Row 0 uses only L[0][0]. n = 1 works the same way.
- y is written for every row.
=== gemm
Algorithm
1. For each row i of C (i from 0 while i < ni):
   a. Scale the row by beta: C[i][j] = beta * C[i][j] for all j < nj.
   b. For k from 0 while k < nk: s = alpha * A[i][k]; C[i][j] = C[i][j] + s * B[k][j] for all j < nj.
2. Return.

Edge cases
- ni, nj or nk equal to 1 work through the same steps (single iterations).
- Each C[i][j] receives the products in increasing k, the same order as a straightforward triple loop.
=== 2mm
Algorithm
1. Phase 1 (tmp = alpha * A * B), for each row i of tmp:
   - Set the tmp row to zero (all nj entries), since tmp has undefined contents.
   - For k from 0 while k < nk: s = alpha * A[i][k]; tmp[i][j] = tmp[i][j] + s * B[k][j] for all j < nj.
2. Phase 2 (D = beta * D + tmp * C), for each row i of D:
   - Scale the D row by beta (all nl entries).
   - For j from 0 while j < nj: D[i][l] = D[i][l] + tmp[i][j] * C[j][l] for all l < nl.
3. Return.

Edge cases
- All sizes may be 1.
- No element beyond the end of any row is accessed; row lengths are nj (tmp, B), nk (A) and nl (C, D).
- Every output element receives its products in increasing order of the summation index.
=== 3mm
Algorithm
Each of the three products X = Y * Z (X is p x q, Y is p x r, Z is r x q) uses the same loop nest.
1. Three products, in this order:
   a. E = A * B: p = ni, r = nk, q = nj.
   b. F = C * D: p = nj, r = nm, q = nl.
   c. G = E * F: p = ni, r = nj, q = nl.
   For each product, for each row i:
   - Set row i of X to zero (all q entries), because E, F and G have undefined contents.
   - For k from 0 while k < r: X[i][j] = X[i][j] + Y[i][k] * Z[k][j] for all j < q.
2. Return.

Edge cases
- Any size may be 1.
- The third product must start only after E and F are complete.
- Each output element accumulates its products in increasing k.
=== syrk
Algorithm
1. For each row i from 0 while i < n:
   For j from 0 while j <= i (lower triangle including the diagonal):
   - Dot product d = sum over k (k < m) of A[i][k] * A[j][k] (both rows of A are contiguous).
   - C[i][j] = beta * C[i][j] + alpha * d.
2. Return.

Edge cases
- Entries with j > i are never read or written.
- m = 1: single products. n = 1: only C[0][0].
=== trmm
Algorithm
Result row i = alpha * (B row i + sum over k > i of A[k][i] * B row k). Rows are processed in increasing i: row i only needs rows k > i, which have not been overwritten yet, so the update can be done in place.
1. For each i from 0 while i < m:
   a. For k from i+1 while k < m: B[i][j] = B[i][j] + A[k][i] * B[k][j] for all j < n.
   b. Scale row i by alpha.
2. Return.

Edge cases
- The diagonal of A is taken as 1 (row i itself is added with factor 1, not multiplied by A[i][i]); entries of A with k <= i are never read.
- i = m-1: no k iterations, the row is only scaled. m = 1: B = alpha * B.
- Each element receives the products in increasing k.
=== jacobi1d
Algorithm
1. Do 2 * tsteps half-steps. Each half-step reads from a source array and writes to a destination array; afterwards source and destination are swapped, so the first half-step goes A to B and the second B to A.
2. In each half-step: for i from 1 while i < n - 1: dst[i] = (src[i-1] + src[i] + src[i+1]) / 3.0, adding the three values in this order.
3. After an even number of half-steps the roles are back to A and B. Return.

Edge cases
- n = 3: one interior element. Elements 0 and n-1 are never written in either array.
- The highest index read is n-1 (the last interior element reads i+1 = n-1).
- tsteps = 1: two half-steps.
=== jacobi2d
Algorithm
1. Do 2 * tsteps half-steps; A is the source and B the destination of the first half-step, and the two are swapped after each one.
2. In each half-step, for each row i from 1 while i < n - 1, for each column j from 1 while j < n - 1:
   sum = centre (row i, column j) + left (column j-1) + right (column j+1) + row i+1 (column j) + row i-1 (column j), added in this order; dst[i][j] = 0.2 * sum.
3. Return.

Edge cases
- n = 3: a single interior element. Border rows and columns are never written.
- No read beyond column n-1 of a row.
- The sum is formed in the same order for every element.

3. Return.

Edge cases
- n = 3: a single interior element. Border rows and columns are never written.

=== heat3d.L0
Algorithm
1. Do 2 * tsteps half-steps; A is the source and B the destination of the first half-step, swapped after every half-step (first A to B, then B to A). Element (i, j, k) is at index (i*n + j)*n + k.
2. In each half-step, for i from 1 to n-2, for j from 1 to n-2, for k from 1 to n-2, with c = source(i, j, k):
   d_i = source(i+1, j, k) - (c + c) + source(i-1, j, k)
   d_j = source(i, j+1, k) - (c + c) + source(i, j-1, k)
   d_k = source(i, j, k+1) - (c + c) + source(i, j, k-1)
   dst(i, j, k) = ((0.125*d_i + 0.125*d_j) + 0.125*d_k) + c, in this order (the centre value is added last).
3. Return.

Edge cases
- n = 3: a single interior point per half-step. Boundary elements (any index 0 or n-1) are never written.
- tsteps = 1: two half-steps.
=== heat3d
Algorithm
1. Do 2 * tsteps half-steps; A is the source and B the destination of the first half-step, swapped after every half-step (first A to B, then B to A). Element (i, j, k) is at index (i*n + j)*n + k.
2. In each half-step, for i from 1 to n-2, for j from 1 to n-2, for k from 1 to n-2, with c = source(i, j, k):

=== spmv
Algorithm
1. For each row i from 0 while i < nrows:
   - start = rowptr[i], end = rowptr[i+1]; sum = 0.0.
   - For k from start while k < end: sum = sum + val[k] * x[col[k]].
   - y[i] = sum.
2. Return.

Edge cases
- Empty rows (rowptr[i] = rowptr[i+1]): no products are added and y[i] = 0.0 is stored; y must always be written because it is undefined on entry.
- nrows = 1: one row. rowptr has nrows+1 entries, so reading rowptr[i+1] is always valid.
- The products are added in the order of k, like a sequential sum.
=== prefix_sum
Algorithm
1. s = 0.
2. For i from 0 while i < n: s = s + a[i]; out[i] = s.
3. Return.

Edge cases
- n = 1: out[0] = a[0]. The sum includes the element at the same position (inclusive prefix sum).
- 64-bit integer addition; overflow wraps, as in two's complement arithmetic.
- Each output depends on the previous one.
=== histogram
Algorithm
1. Clear hist: for b from 0 while b < nbins: hist[b] = 0. This is needed because hist is undefined on entry.
2. Count: for i from 0 while i < n: hist[data[i]] = hist[data[i]] + 1.
3. Return.

Edge cases
- nbins = 1 or n = 1: each step runs once.
- Every data value is between 0 and nbins-1, so hist[value] is always inside hist; no bounds check is needed.
- Repeated values simply increment the same counter several times.
=== popcount
Algorithm
1. For each element i from 0 while i < n, with v = a[i] as an unsigned 64-bit value:
   - v = v - ((v >> 1) & 0x5555555555555555)                          (2-bit counts)
   - v = (v & 0x3333333333333333) + ((v >> 2) & 0x3333333333333333)   (4-bit counts)
   - v = (v + (v >> 4)) & 0x0F0F0F0F0F0F0F0F                          (8-bit counts)
   - v = (v * 0x0101010101010101 mod 2^64) >> 56                      (the highest 8 bits hold the total)
   - counts[i] = v.
2. Return.

Edge cases
- n = 1: one element. All 64 bits are counted, including the top bit, so all shifts are unsigned.
- The count is between 0 and 64 and is stored as a full 64-bit value.
=== lower_bound.L0
Algorithm
1. For each key t from 0 while t < q:
   - lo = 0, hi = n.
   - Binary search while lo < hi: mid = lo + ((hi - lo) / 2); if sorted[mid] < keys[t] (signed values), lo = mid + 1, else hi = mid.
   - idx[t] = lo.
2. Return.

Edge cases
- Key smaller than or equal to every element: the result is 0. Key larger than every element: lo reaches n and n is stored.
- Repeated values: the search keeps moving hi down on equality, so it returns the first position whose element is not smaller than the key.
- n = 1: one comparison. Negative values are handled because all comparisons are signed.
- Only indices 0 to n-1 of sorted are ever read (mid < hi <= n).
=== lower_bound
Algorithm
1. For each key t from 0 while t < q:
   - lo = 0, hi = n.
   - Binary search while lo < hi: mid = (lo + hi) / 2 (lo + hi cannot overflow); if sorted[mid] < keys[t] (signed values), lo = mid + 1, else hi = mid.
   - idx[t] = lo.
2. Return.

Edge cases
- Key smaller than or equal to every element: the result is 0. Key larger than every element: lo reaches n and n is stored.
- Repeated values: the search keeps moving hi down on equality, so it returns the first position whose element is not smaller than the key.
- n = 1: one comparison. Negative values are handled because all comparisons are signed.
- Only indices 0 to n-1 of sorted are ever read (mid < hi <= n).
=== sort8.L0
Algorithm
1. For each group of 8 consecutive elements (n / 8 groups):
   Apply the 19 compare-exchange steps of the given network, in the given order:
   (0,1) (2,3) (4,5) (6,7) (0,2) (1,3) (4,6) (5,7) (1,2) (5,6) (0,4) (3,7) (1,5) (2,6) (1,4) (3,6) (2,4) (3,5) (3,4).
   Each compare-exchange (p, q): if element p > element q (signed values), exchange the two.
2. Return.

Edge cases
- n = 8: one group. n is a positive multiple of 8, so there is no partial group.
- The comparison is signed, so negative values sort first. Equal values are not exchanged.
- Only the current group is read and written.
=== sort8
Algorithm
1. For each group of 8 consecutive elements (n / 8 groups): insertion sort of the 8 elements e[0..7]:
   - for i from 1 to 7: key = e[i]; j = i - 1;
     while j >= 0 and e[j] > key (signed comparison): e[j+1] = e[j]; j = j - 1;
     e[j+1] = key.
2. Return.

Edge cases
- n = 8: one group. n is a positive multiple of 8, so there is no partial group.
- Elements are signed 64-bit; the comparison must be signed (negative values sort first).
- Equal elements are not moved past each other (strict > comparison), and the inner step never reads outside the current group (j >= 0 is tested before the comparison).
